# 踩过的坑（按代价排序）

这些都是真机实测出来的，不是猜的。改代码前先读一遍。

## 1. LaMa 的输入约定：掩膜要 0/1，图要 0–1

ONNX 版（Carve/LaMa-ONNX）对输入极其挑剔：

| 喂法 | 结果 |
|---|---|
| 图 0–1，掩膜 0/1 | ✅ 正确 |
| 图 0–1，掩膜 0–255 | ❌ **输出全白图**（均值 254.8），不报错 |
| 图 0–255，掩膜 0/1 | ❌ 无意义输出 |

最坑的是它不报错，看起来像「模型坏了」。定位方法：**先跑官方 demo**。
拿模型作者给的 原图/掩膜/参考输出 三件套跑一遍，diff 只有 2% 就说明模型没问题，是协议喂错了。

TorchScript 版（big-lama.pt）宽容得多，本 skill 用的是它。

## 2. LaMa 的 ROI：拉伸，不要 padding

| 喂法 | 结果 |
|---|---|
| 裁 512×224 直接拉伸到 512×512 | ✅ 纹理重建准确 |
| 裁 512×224 补黑边到 512×512 | ❌ **黑边被当成真实内容，往洞里画暗块** |
| 原样喂 512×512 左上角 | ❌ 只看到一小块，浮雕被臆造成通用团块 |

LaMa 输入固定 512×512。水印是「宽而扁」的条带，正确做法是纵向拉伸铺满，
掩膜同步拉伸，修完再缩回原比例。

## 3. 掩膜膨胀半径：3px，别贪

- 15px → 一片糊，浮雕花纹全没
- 7px → 还能接受，但高细节区变软
- **3px@1080p** → 覆盖抗锯齿边 + H.264 振铃，且保住细节

下限是「字形 bbox 外扩 3px」。1920 以外按宽度比例缩放（\`common.dilate_px\`）。

## 4. 只替换掩膜内像素

\`\`\`python
res[y0:y1, x0:x1][sel] = back[sel]   # ✅
res[y0:y1, x0:x1] = back            # ❌ 整块贴回，边界留下矩形接缝
\`\`\`

LaMa 输出的边缘和原图不可能逐像素一致，整块贴回就是在 ROI 边界画一个框。

## 5. 后端选择：CoreML 比 CPU 还慢

同一台 M5，同一模型：

| 后端 | 每帧 |
|---|---|
| ONNX Runtime + CoreML EP | **4.07 s** |
| ONNX Runtime + CPU | 2.10 s |
| torch + MPS | **0.22 s** |
| torch + CPU | 6.0 s |

CoreML EP 会把算子拆碎反复调度+搬数据，结果比纯 CPU 还慢一倍。
**别假设「有硬件加速就一定快」，一定要实测。**

## 6. 批量推理没有吞吐收益

| batch | 每帧 |
|---|---|
| 1 | 222 ms |
| 2 | 228 ms |
| 4 | 240 ms |
| 8 | 241 ms |

模型吃不满 GPU，加大 batch 只是把同样的工作串起来。同理 fp16 也不行——
TorchScript 里的自定义 FourierUnitJIT 算子不支持半精度，直接抛错。

**结论：想快只能换方法，不能优化这条链路。**

## 7. alpha 反解必须逐像素，且必须用差分法估

| 估法 | 结果 | 评价 |
|---|---|---|
| 单帧 + inpaint 当背景代理做线性拟合 | α≈0.50，R²=0.3 | ❌ 系统性偏低 |
| 多帧差分 \`Δobs/Δbg = 1−α\` | α≈0.70，C≈255 | ✅ 正确 |

差分只要求「该像素背景在采样帧之间确实变了」。挑背景差异大的帧对（暗场对暗场信号最强）。

单帧法错在：inpaint 出来的背景代理本身有偏，回归出来的 α 会稳定地偏低 0.2 左右。

## 8. alpha 反解的物理上限

α=0.7 意味着观测值被压在 \`178.5–255\` 这 76.5 级里（原始 256 级）。反解除以 0.3，
**噪声和压缩块放大 3.3 倍**。

更致命的是饱和：背景本身接近白（天空、雪、白墙）时，水印把那块顶到了 255，
**信息已经被削平，物理上不可恢复**。这种情况算出来的 α 甚至会是负数。

所以 4 号方法只适合平缓/暗背景，或者作为 LaMa 的预处理。

## 9. delogo 只做边界插值

delogo 不是重建，是「拿框边往框内插值填充」。框内原本有连续结构（浮雕、树枝、衣褶）时，
插出来的必然不是原物：**横条糊 + 棋盘格**。

一个反直觉的实测：**同一个 delogo 连跑两遍，输出文件 sha256 完全相同**。
第二遍是在第一遍已填好的像素上再插一次，输入没变，结果必然一样。别指望「多跑几遍更干净」。

\`removelogo\`（另一个 ffmpeg 滤镜）更差：它是给静态电视台标设计的，输出是灰色糊块。

## 10. ffprobe 的宽高会骗人

竖屏视频（手机拍摄）带 rotation 元数据时，ffmpeg 解码会自动旋转，
实际帧尺寸和 ffprobe 报的**宽高互换**。用错尺寸读 \`rawvideo\` 会错位撕裂。

本 skill 的 \`common.actual_frame_size()\` 解一帧核对字节数，所有脚本都经过它。

## 11. ffmpeg 9 的选项变化

| 旧写法 | 现状 |
|---|---|
| \`-vsync 0\` | 已移除，用 \`-fps_mode\` 或不写 |
| \`-of csv:s\` | 不存在，用 \`-of json\` |
| 输出到 \`/dev/null\` 不带 \`-f\` | 报 "Unable to choose an output format" |
| \`nb_frames\` 与 \`时长×fps\` 对不上 | 正常，以 \`nb_frames\` 为准 |

## 12. 验证脚本自己也会错

早期版本用 \`g[mask]\` 在二维数组上取三维索引，直接 IndexError，白跑一次全片扫描。
**验证脚本也要先用小样本跑通再上全片。**

而且「看起来没问题」不算过：一定要有可复现的数字（残留量、去除率、PSNR/SSIM）。
