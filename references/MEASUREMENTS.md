# 实测数据（真实 B站 上传视频）

样本：1920×1080 / 30fps / 286.5s / H.264 11.9 Mbps / AAC，
UP 主名「阿娇娇娇兒」+ bilibili 台标，左上角。

## 水印的物理参数

| 项目 | 实测 |
|---|---|
| 精确字形范围 | x 37–377, y 20–96（341×77 px，占画面 0.39%） |
| 外扩 3px 安全框 | x 34–380, y 17–99（346×82） |
| 位置稳定性 | 41 帧模板匹配，坐标完全一致（无移动/缩放/淡入淡出） |
| 叠加模型 | obs = alpha*255 + (1-alpha)*bg，纯白（C≈251–258） |
| alpha | 中位数 **0.70**（平缓处 0.68–0.72，边缘 0.09–0.75） |
| 描边/阴影 | **无**（亮天空帧下字母内部仍是灰而非黑） |
| 全片存在性 | 0–285s 全程，41 个采样点全部命中 |

**这些数字是判定的依据。** 换个 UP 主主名长度会变，框会变，但
「纯白、alpha≈0.7、无描边、静态、台标在右」这几条不变——检测器就靠这几条。

## 速度实测（Apple M5, 8 核 GPU, 16 GB）

单帧端到端 **262–311 ms**（系统空闲 0.26 s，有后台抢占 0.31 s）：

| 环节 | 每帧 | 占比 |
|---|---|---|
| LaMa 推理（MPS） | ~230 ms | ~88% |
| GPU→CPU 回传 | ~8 ms | ~3% |
| 编码 libx264 crf18 medium | ~10 ms | ~4% |
| 解码 + opencv + IO | ~14 ms | ~5% |

8593 帧整片实测 **44 分 40 秒**（预算 38 分钟，差值来自后台进程争抢 GPU）。

编码器对比（900 帧 / 30 秒测试片）：

| 设置 | 耗时 |
|---|---|
| libx264 ultrafast | 1.1 s |
| libx264 veryfast | 2.4 s |
| libx264 medium | 9.2 s（默认） |
| libx264 slow | 8.6 s |
| h264_videotoolbox | 2.45 s |

**编码只占 4%，不值得为它换硬编，除非文件大小敏感。**

## 检测器在真实样本上的表现

| 指标 | 值 |
|---|---|
| 自动检出 | 是（无需 --bbox） |
| 检出框 | x 37 y 36, 341×61（高度比真实少 16px，见下） |
| 字形召回（外扩 3px 后） | **0.993** |
| 字形精度（外扩 3px 后） | 0.60 |
| 静态性 | 1.0（41 帧全部命中） |
| 台标签名 | right 0.39 / left 0.29 |

**为什么检出框的高度偏小**：能量图对「细笔画」敏感，而台标 i 的点和字母上端是极细的高光，
在降采样后能量被削弱。所以 build_tight() 会在候选框基础上**额外向上/下各扩 0.55×高度**，
再由生成的字形掩膜自己定最终框。这个设计让召回从 0.61 提到 0.99。

**精度 0.60 的含义**：掩膜比字形宽一圈（外扩 3px 后）。这是有意的——
宁可多修一点，也不要漏。因为只替换掩膜内像素，多出来的部分被 LaMa 用周围像素填补，
视觉上无缝；漏掉的部分则会留下白边，一眼就能看见。

## 掩膜膨胀对结果的影响（视觉判断）

| 膨胀 | 浮雕纹理 | 残留 |
|---|---|---|
| 3 px | 保留 | 无 |
| 7 px | 略软 | 无 |
| 17 px | **整片抹平** | 无 |

所以默认 3px，只有检测器报告 alpha_max > 0.9（近乎不透明）时才考虑加大。
